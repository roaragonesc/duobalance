Los endpoints se documentan en [README de API](../apps/api/README.md) y en sus
fuentes OpenAPI, no se infieren semánticamente de nombres de archivos.
Recursos binarios/SVG y documentación UX quedan
fuera del inventario automático; su revisión es manual. El checker tampoco
certifica autorización, accesibilidad ni compatibilidad semántica de DTOs.

`PendingBalance` se define en `apps/web/src/features/balance/types.ts` y mantiene
su reexport desde dashboard. Expenses consume al propietario directamente:
se elimina el ciclo de tipos sin alterar campos ni imports públicos existentes.

Los componentes compartidos viven en `apps/web/src/components/`. Los
componentes que solo sirven a una funcionalidad permanecen en
`apps/web/src/features/<feature>/components/`.

## Compartidos

| Área | Ejemplos | Uso |
| --- | --- | --- |
| `layout/` | `AppLayout`, `AuthLayout`, `OnboardingLayout`, `SimpleLayout` | Estructura común y navegación de páginas |
| `ui/` | `TextField`, `SubmitButton`, `FormAlert`, `ConfirmDialog` | Controles y estados reutilizables |
| `ui/` | `MonthSelector`, `EmptyState`, `RetryPanel`, `StatusMessage` | Estados y patrones transversales |
| `ui/` | `Logo`, `MintWave`, `DonutChart`, `icons` | Marca y presentación compartida |

## Por funcionalidad

| Funcionalidad | Ejemplos |
| --- | --- |
| `auth` | `AuthCard`, `PasswordRequirements`, `ResendConfirmation` |
| `balance` | `BalanceView`, `SettlementForm`, `SettlementsTable` |
| `dashboard` | `DashboardView`, `SummaryCards`, `RecentExpenses` |
| `expenses` | `ExpenseForm`, `ExpensesView`, `AddExpenseLink` |
| `incomes` | `IncomeForm`, `IncomesView` |
| `spaces` | `OnboardingStepper`, `SplitMethodForm`, `InvitationLink` |

Antes de crear un componente, busca si ya existe uno con semántica y estados
equivalentes. Mueve un componente a `components/` compartido solo cuando varias
features lo usen realmente y su API pueda mantenerse neutral.
